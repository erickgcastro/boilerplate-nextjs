# Internacionalização

O projeto usa next-intl 4. Os locales e o padrão ficam em `src/i18n/routing.ts`.

## URLs

- Toda página tem o locale no começo do caminho: `/en/products`, `/pt-br/products`.
- `src/proxy.ts` roda o middleware do next-intl. Quem acessa um caminho sem locale é redirecionado para o locale detectado pelo cookie ou pelo `Accept-Language` do navegador.
- O proxy ignora `/api`, `/trpc`, `/_next`, `/_vercel` e qualquer caminho com extensão de arquivo.
- Locale que não existe cai em `notFound()` no layout.

## Mensagens

- Os textos ficam em `public/locales/<locale>/messages.json`, e as mensagens de erro em `public/locales/<locale>/errors.json`.
- `src/i18n/request.ts` carrega os dois arquivos e junta tudo num objeto só. Uma chave de primeiro nível que exista nos dois arquivos é sobrescrita pela de `errors.json`.
- Toda chave nova entra em todos os locales.
- As chaves são agrupadas por feature:

```json
{
  "product": {
    "title": "Products",
    "loading": "Loading...",
    "delete": {
      "label": "Delete",
      "success": "Product deleted",
      "error": "Could not delete the product"
    }
  }
}
```

## Uso

```tsx
const t = useTranslations();
return <h1>{t("product.title")}</h1>;
```

- `useTranslations` funciona em client components e em server components não assíncronos. Em server component `async`, use `await getTranslations()` de `next-intl/server`.
- Nenhum texto visível fica fixo no JSX, incluindo label de botão, estado de carregamento e mensagem de alerta.
- Para navegar, importe `Link`, `useRouter`, `redirect`, `usePathname` e `getPathname` de `@/i18n/navigation`, não de `next/link` ou `next/navigation`. Eles mantêm o locale atual na URL.
- A exceção são os route handlers de `/api`, que não têm locale: o router do next-intl transformaria `/api/<rota>` em `/en/api/<rota>`, que não existe. Para eles, use `window.location.assign("/api/<rota>")`.
